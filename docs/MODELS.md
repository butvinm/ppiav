# Таблицы слоёв моделей C3AE

Ниже три таблицы:

1. **Оригинальная C3AE** — как опубликована в статье (Conv1 со stride 1, ReLU,
   учёт параметров BN включает running-статистики).
2. **Наша plaintext-версия C3AE** — `models/models/c3ae.py` в том виде, в каком
   реально обучается (`first_stride=2`, ReLU). Conv1 со stride 2 уменьшает
   пространственные размеры на раннем этапе и даёт ускорение ~4.5×; при этом
   убирается Pool3, а вход Flatten уменьшается с 512 признаков (`4×4×32`,
   как в статье) до 128 (`2×2×32`). Размер выходного скалярного слоя при
   этом не меняется — в обеих схемах он один скаляр.
3. **Наша FHE-версия C3AE** — `models/models/c3ae_fhe.py`, топологически
   идентична (2), но все ReLU заменены на Quad (`x ↦ x²`), благодаря чему
   сеть компилируется Orion в CKKS-схему.

MACC считается только для conv / linear слоёв (как в статье).

## Нормализация входа

Картинка из UTKFace грузится через `models/models/utkface.py`: ресайз до
64×64 `PIL`-ом (bilinear по умолчанию), затем `float32 / 255.0` и
аффинная нормализация `(x − 0.5) / 0.5`, то есть итоговый тензор лежит в
**[−1, 1]** (channels-first, RGB). На VPS-инференсе и в FHE-пайплайне на
вход Conv1 подаётся именно такой нормализованный тензор; никакой
mean/std из ImageNet не используется.

## Семантика голов Feat / Pred

В оригинальной статье C3AE решается задача регрессии возраста с
«two-points age representation»: `Feat` — K-мерный вектор распределения по
возрастным бинам (обучается soft-label cross-entropy), `Pred` — скалярная
регрессия возраста в годах (L1-loss). У нас задача другая — **бинарная
верификация совершеннолетия (18+)**. Из исходной двухголовой схемы сохранена
только топология `128 → 12 → 1`, обучение полностью переформулировано
(`models/models/train.py`):

- таргет — `{0, 1}` (моложе / старше 18 лет, порог берётся из метаданных
  UTKFace);
- лосс — асимметричный BCE с `fpr_weight=40` (false positive штрафуется в
  40 раз сильнее false negative), на выход `Pred` накладывается `sigmoid`;
- никакой age-bin-supervision на `Feat` нет — это просто 12-мерный bottleneck,
  обучаемый end-to-end под бинарную задачу.

Таким образом:

- **FC1** — 12-мерный эмбеддинг лица (bottleneck), без отдельного лосса.
- **FC2** — скаляр-**логит** классификатора 18+. В plaintext-инференсе
  предсказание — `sigmoid(FC2) ≥ 0.5`; в FHE-пайплайне `result_ct` после
  совместной расшифровки — тот же сырой логит, и verdict-логика сравнивает
  его со знаковым порогом (`≥ 0` → adult), что эквивалентно
  `sigmoid(·) ≥ 0.5`.

## 1. Оригинальная C3AE (статья)

В статье `BN + ReLU + AvgPool` объединены в одну строку «BRA»; ниже она
развёрнута построчно. Распределение параметров соответствует итогам статьи:
**128 на BN** = γ + β + running_mean + running_var = 4·32. Важно: в PyTorch
`nn.BatchNorm2d.parameters()` возвращает только обучаемые γ, β (= 2·32 = 64);
`running_mean` и `running_var` хранятся как **buffers**, не parameters.
Авторы статьи, по всей видимости, считают параметрами всё содержимое
`state_dict`, поэтому у них получается 128, а у нас в таблице 2 — 64
(см. сноску под таблицей). 0 для ReLU / AvgPool. Параметры Conv включают
bias. Выход модели — скалярная **регрессия возраста** (R), а не логит
классификатора.

Pool3 отсутствует (`has_pool3 = first_stride == 1`). У всех Conv-слоёв кроме

## 4. FHE-стоимость одного инференса (LogN=16)

Числа получены прогоном `ppiav-cli infer` на VPS с инструментированными
обёртками вокруг `lattigo`-примитивов (sample_idx=12, age=20, forward 272.3s,
peak RSS 98.7 GB). LT-диагональ — это одно `MulCt-Plain` (умножение
шифротекста на plaintext-вес) внутри BSGS-формы линейного преобразования;
`MulCt-Ct` — это умножение двух шифротекстов (только в Quad-активациях,
требует `Relinearize` + `Rescale`).

| Слой      | op               | MulCt-Ct | LT diagonals (MulCt-Plain) |
| --------- | ---------------- | -------- | -------------------------- |
| conv1     | linear_transform | 0        | 128                        |
| act1      | quad             | 1        | -                          |
| pool1     | linear_transform | 0        | 577                        |
| conv2     | linear_transform | 0        | **4,379**                  |
| act2      | quad             | 1        | -                          |
| pool2     | linear_transform | 0        | 184                        |
| conv3     | linear_transform | 0        | 1,024                      |
| act3      | quad             | 1        | -                          |
| conv4     | linear_transform | 0        | 256                        |
| act4      | quad             | 1        | -                          |
| conv5     | linear_transform | 0        | 105                        |
| act5      | quad             | 1        | -                          |
| fc1       | linear_transform | 0        | 16                         |
| act6      | quad             | 1        | -                          |
| fc2       | linear_transform | 0        | 12                         |
| **Итого** |                  | **6**    | **6,681**                  |

conv2 — горячая точка BSGS: **65% всех LT-диагоналей** сети (4,379 из 6,681).
Это согласуется с максимумом по plaintext MACC (таблица 3), но соотношение
нелинейное: conv1 имеет 830,304 MACC и всего 128 диагоналей, потому что
вход — 3 канала; у conv2 уже 32→32 канала и spatial 15×15, и плотность
диагоналей в BSGS-форме растёт нелинейно с C_in·C_out.

Bootstrap не требуется: 15 мультипликативных уровней цепочки CKKS при
LogN=16 покрывают всю модель (6 уровней на Quad + 9 на linear_transform).
Это нижняя граница LogN для этой архитектуры — при LogN=15 уровней не
хватит, потребуется либо bootstrap, либо удаление одного Quad.
